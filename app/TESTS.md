# What the app tests protect

There are two suites:

- **Unit and component tests:** 308 vitest tests in `src/**/*.test.ts(x)`, run under jsdom with `npm test -w app`.
- **End-to-end tests:** about 49 Playwright tests in `e2e/`, run against a production build in Chromium with `npm run e2e -w app`. Axe accessibility checks run separately with `npm run a11y -w app`.

CI runs both through `npm run verify` and the `a11y` job.

**What goes where.** The unit tests cover logic the app owns: drop-position resolution, canvas geometry and zoom, label collision, undo/redo, the saved-design codec, and the stores. Component tests check _wiring_, one test per control; the logic behind each control is tested in its own module. End-to-end tests cover only what jsdom can't: real drag-and-drop, layout and scrolling, printing, the service worker, real `localStorage` across reloads, and axe. Engine behaviour (scoring, fitting, warnings) is tested in `packages/engine`. Where the app wraps an engine function in one line (`isInsideRegion`, `validateOutlineEdit`), it has one test of the wrapping, not a copy of the engine's cases.

Severity describes what goes wrong for a user if the guarded behaviour breaks:

- **Critical**: the app doesn't load or work.
- **High**: the user's garden is lost or corrupted, or the plan is silently wrong.
- **Medium**: a feature visibly misbehaves.
- **Low**: cosmetic or wording.

# What the ETL tests protect

There are 252 vitest tests in `src/**/*.test.ts`. Run them with `npm test -w packages/etl`. CI runs them through `npm run verify`. No test touches the network: GBIF and OpenFarm are reached through injected transports, stubbed in tests, and committed caches.

The ETL builds `data/plants.json`, the dataset the whole app trusts, from OpenFarm's archived dump, hand-verified tables (spacing, companions, moisture, exclusions) and curated records. Its failure mode is bad or missing data that ships silently. The tests fall into three kinds:

- **Gates** on the committed dataset (`merge/shipped-dataset.test.ts`).
- **Rule tests** for each merge, join and validation step, on fixtures.
- **Content tests** on each hand-maintained table. These check only what the table's schema _can't_ enforce; anything the schema guarantees is tested once, in the schema's own test file.

Severity describes what goes wrong for users if the guarded behaviour breaks:

- **High**: wrong, missing or invalid data ships.
- **Medium**: the build fails or misbehaves visibly.
- **Low**: a message, log or path.

## `merge/shipped-dataset.test.ts`: the gate on what ships

`npm run build:data` is run by hand, and CI never regenerates `data/plants.json`. These three tests are the only check between that file and users.

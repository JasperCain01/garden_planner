# What the engine tests protect

There are 339 vitest tests in `src/**/*.test.ts` (table-driven cases counted individually). Run them with `npm test -w packages/engine`. CI runs them through `npm run verify`.

The engine decides which crops to recommend, how many fit in a bed, and which warnings to raise. Its failures are therefore mostly silent: a plausible but wrong count or ranking. Most tests derive their expected values by hand in a comment (worked examples), and the spacing engine also has property-based tests over seeded random polygons.

**Real data.** The `dataset.test.ts` files run the engine over the committed `data/plants.json`. They are written as _properties_ of whatever data ships, so a data refresh doesn't break them. The record counts themselves are pinned once, in `packages/etl/src/merge/shipped-dataset.test.ts`.

**Layering.** Each behaviour is tested at the layer that implements it. Higher layers (rank, evaluate) test what _they_ add (ordering, routing) and don't repeat the scenario tests of the layers below. For example, "full-sun crop in full shade is unsuitable" belongs to `light.test.ts`. The cap that makes it disqualifying belongs to `score.test.ts`, and the warning it raises to `suitability-rules.test.ts`.

Severity describes what goes wrong for a user if the guarded behaviour breaks:

- **High**: a silently wrong recommendation, count or warning.
- **Medium**: a visible misbehaviour or error.
- **Low**: wording.
